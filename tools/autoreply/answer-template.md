# 实质回信模板（读者来信）

适用场景：读者的来信 / 留言已经收到（确认信由 `reply.py` 自动发出），
现在要写**给出实质回答**的那封回信。

## 结构

**1. 开场（人文关怀，1～3 句）**

- 谢谢你的来信，很高兴你愿意把这些疑惑、问题、心事跟我分享。
- 可以承接对方的具体情绪：读到「……」那句，我停下来想了很久。
- ❌ 不要复述「你问的问题是……」，不要「关于你提到的 XX 问题」这种客服式开头。

**2. 过渡（1 句）**

- 你的话我也想了很久，现在把想到的写给你。
- 或者说：说不上是答案，只是我的一些想法。

**3. 正文（直接讲结论和理由）**

- 先给判断，再给两三条能落到具体动作上的做法。
- 引文只在真正支撑观点时出现，用作者自己的话说出来，不列「参考资料」。
- ❌ 不写检索 / 思考过程：不出现「我们查了知识库」「读了最近几篇文章」「搜索了」
  「把想法整理如下」「模型 / 训练 / 提示词」这类话。读者要的是答案，不是工作流。

**4. 结尾（固定，不添加内部动作）**

- 你的问题有普遍性，我们会把这篇回答整理成一篇公开笔记，发在网站的「读者来信」栏目，
  方便有同样困惑的人看到。
- 欢迎你继续来信，直接回复这封邮件就能找到我。
- ❌ 不提交知识库、入库、归档、沉淀、整理进资料库等内部流程。

**5. 落款（固定，一字不改）**

```
我是子喻，【观子喻知】的主理人。向外体察，读懂万象，启思创造，拥抱探索。
https://yuspectra.github.io/chaiAI/
```

## 禁用清单

| 禁用 | 原因 |
| --- | --- |
| 杨教练 | 旧称，已废弃 |
| 知识库 / 沉淀 / 入库 / 归档 / 资料库 | 内部流程，不告诉读者 |
| 我们查了 / 我们读了 / 检索 / 整理如下 | 思考过程，读者不需要 |
| 「你问的问题是……」式复述 | 客服腔，拉开距离 |

## 语气

- 像写信，不像客服；像一个人坐下来认真回话。
- 用「我」，不用「我们团队」「本平台」。
- 短句，少形容词；允许留白，不强行乐观。
